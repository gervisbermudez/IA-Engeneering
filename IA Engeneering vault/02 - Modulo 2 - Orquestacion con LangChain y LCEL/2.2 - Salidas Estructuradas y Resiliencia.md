# 2.2 Salidas Estructuradas y Resiliencia en Cadenas

## 🎯 Objetivo de la Unidad
Garantizar que los LLMs devuelvan objetos tipados con contratos formales usando `.with_structured_output()` y diseñar cadenas resilientes ante errores de red o formato con `.with_retry()`.

---

## 1. El Riesgo de las Salidas en Texto Libre

El texto libre es probabilístico: el modelo puede cambiar las claves de un JSON, alucinar campos faltantes o devolver formatos rotos (`'''json ... '''`).

> [!WARNING]
> Nunca uses `json.loads(respuesta_texto)` a ciegas en producción. Una sola comilla mal escapada causará una excepción no controlada en tu backend.

---

## 2. Salidas Estructuradas con `with_structured_output`

LangChain abstrae el uso de **Tool Calling / Function Calling** de OpenAI y Anthropic mediante `.with_structured_output(ModeloPydantic)`:

```python
from enum import Enum
from typing import List
from pydantic import BaseModel, Field
from langchain_openai import ChatOpenAI

class Criticidad(str, Enum):
    BAJA = "baja"
    MEDIA = "media"
    ALTA = "alta"

class AnalisisIncidente(BaseModel):
    tecnologias: List[str] = Field(description="Lista de tecnologías o servicios involucrados")
    nivel_de_criticidad: Criticidad = Field(description="Severidad del incidente")
    resumen_tecnico: str = Field(description="Explicación concisa del problema técnico")

modelo = ChatOpenAI(model="gpt-4o-mini", temperature=0.0)
modelo_estructurado = modelo.with_structured_output(AnalisisIncidente)
```

Al pasar por este método:
1. El LLM se ve forzado a completar el esquema JSON Schema derivado del modelo de Pydantic.
2. La salida devuelta por la cadena es directamente una instancia validada de `AnalisisIncidente`.

## 3. Resiliencia: Reintentos con `with_retry`

En entornos reales, los LLMs pueden fallar por problemas transitorios:
* Errores de red (`TimeoutError`, caídas momentáneas).
* Rate limits (`429 Too Many Requests`).
* Respuestas incompletas por límite de tokens.

LangChain permite encadenar reintentos con backoff exponencial automático:

```python
# Reintenta hasta 3 veces con espera exponencial antes de fallar
cadena_resiliente = (
    prompt 
    | modelo.with_structured_output(AnalisisIncidente).with_retry(
        stop_after_attempt=3,
        wait_exponential_jitter=True
    )
)
```

## 4. Ejecución Concurrente con `RunnableParallel`

Si necesitas que un modelo procese dos perspectivas independientes del mismo texto (ej. analizar sentimiento y extraer entidades clave), `RunnableParallel` ejecuta ambas ramas en paralelo sin bloquear:

```python
from langchain_core.runnables import RunnableParallel

analisis_paralelo = RunnableParallel(
    sentimiento=cadena_sentimiento,
    entidades=cadena_entidades
)

# Ambas ramas corren concurrentemente en el Event Loop
resultado = await analisis_paralelo.ainvoke({"texto": "El servidor PostgreSQL falló por exceso de conexiones."})
# resultado = {"sentimiento": "...", "entidades": [...]}
```
