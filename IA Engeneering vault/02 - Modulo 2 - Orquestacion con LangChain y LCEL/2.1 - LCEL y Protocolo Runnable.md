# 2.1 LCEL y el Protocolo Runnable

## 🎯 Objetivo de la Unidad
Abandonar los scripts imperativos manuales ("código espagueti") y aprender a componer flujos de trabajo profesionales mediante **LangChain Expression Language (LCEL)** y el protocolo unificado **Runnable**.

---

## 1. El Problema de la Orquestación Manual

Cuando se utilizan SDKs directos para flujos de varios pasos (ej. traducir → clasificar → extraer JSON → resumir), el desarrollador debe gestionar a mano:
* Inserción y formato de variables en strings.
* Manejo manual de reintentos y tokens.
* Parsing manual de JSON con `json.loads()` vulnerable a fallos.
* Configuración de streaming o paralelismo concurrente complejo con `asyncio.gather`.

### La Solución: LCEL (LangChain Expression Language)
LCEL es una sintaxis declarativa basada en el operador tubería (`|`), inspirada en pipes de Unix:
La salida del componente de la izquierda se convierte automáticamente en la entrada del componente de la derecha.

```python
cadena = prompt | modelo | parser
```

---

## 2. El Protocolo Runnable: La Interfaz Universal

Todos los componentes de LangChain (Prompts, Modelos, Parsers, Herramientas) heredan de la clase base `Runnable`. Esto asegura que todos hablen el mismo lenguaje con una firma estándar:

| Método | Tipo | Descripción |
| :--- | :--- | :--- |
| `invoke(input)` | Síncrono | Ejecuta el runnable sobre una única entrada. |
| `ainvoke(input)` | Asíncrono | Versión `async` no bloqueante de `invoke`. |
| `batch([inputs])` | Síncrono | Ejecuta sobre una lista de entradas optimizando latencia. |
| `abatch([inputs])` | Asíncrono | Versión `async` de `batch`. |
| `stream(input)` | Síncrono | Devuelve un generador de chunks a medida que se producen. |
| `astream(input)` | Asíncrono | Generador asíncrono para streaming en tiempo real. |

> [!TIP]
> **Analogía de la Fábrica**: Cada componente es una estación de trabajo estandarizada. La cinta transportadora (`|`) transporta las piezas de una estación a otra sin importar qué transformación interna realice cada una.

## 3. Composición Básica: Prompt → Modelo → Parser

```python
import asyncio
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

# 1. Definición modular del prompt
prompt = ChatPromptTemplate.from_template("Traduce el siguiente texto a {idioma}: {texto}")

# 2. Modelo
modelo = ChatOpenAI(model="gpt-4o-mini", temperature=0.0)

# 3. Parser de texto plano
parser = StrOutputParser()

# 4. Composición con Pipe
cadena = prompt | modelo | parser

# 5. Invocación asíncrona
async def main():
    resultado = await cadena.ainvoke({"idioma": "español", "texto": "Learning LCEL is powerful."})
    print(resultado)  # "Aprender LCEL es poderoso."

if __name__ == "__main__":
    asyncio.run(main())
```

---

## 4. ChatPromptTemplate: Roles y Modularidad

A diferencia de las f-strings de Python, `ChatPromptTemplate` estructura mensajes con roles (`system`, `human`, `ai`), permitiendo versionado y parametrización limpia:

```python
template = ChatPromptTemplate.from_messages([
    ("system", "Eres un arquitecto de software senior especializado en {especialidad}."),
    ("human", "Explica los beneficios de {tema} en 3 puntos claros.")
])
```

---

## 5. Input Shaping con Lambdas y RunnablePassthrough

Cuando un paso posterior necesita una clave diferente a la que produjo el paso anterior, usamos funciones intermedias (que LCEL convierte automáticamente en Runnables):

```python
cadena_secuencial = (
    cadena_descripcion 
    | (lambda desc: {"descripcion": desc}) 
    | cadena_tweet
)
```
