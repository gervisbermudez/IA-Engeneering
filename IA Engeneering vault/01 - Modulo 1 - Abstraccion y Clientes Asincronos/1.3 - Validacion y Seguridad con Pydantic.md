# 1.3 Validación y Seguridad con Pydantic v2

## 🎯 Objetivo de la Unidad
Establecer contratos de datos estrictos mediante Pydantic v2 para garantizar la integridad de las entradas, evitar llamadas innecesarias a APIs costosas y proteger credenciales sensibles contra fugas en logs.

---

## 1. El Principio de "Fail Fast" (Fallar Rápido)

En ingeniería de IA, enviar una llamada con parámetros erróneos a un LLM implica:
1. Desperdiciar latencia (esperar 1-2 segundos de viaje de red).
2. Posibles costos de facturación o errores de rechazo en la API.
3. Comportamientos no deterministas (alucinaciones).

> [!NOTE]
> Con **Pydantic**, los parámetros se validan localmente en memoria antes de que el cliente realice cualquier conexión de red. Si la temperatura es inválida (`temperature=5.0`), el programa lanza una excepción inmediata antes de consumir cuota.

---

## 2. Modelado de Contratos de Datos (`schemas.py`)

### A. Enum de Proveedores
Evita cadenas de texto libres ("open-ai", "OPENAI", "OpenAi") usando enumeraciones estrictas:

```python
from enum import Enum

class Provider(str, Enum):
    OPENAI = "openai"
    ANTHROPIC = "anthropic"
    GEMINI = "gemini"
```

### B. Validación de Mensajes de Chat (`ChatMessage`)
Garantiza que sólo se permitan los roles soportados universalmente:

```python
from pydantic import BaseModel, Field, field_validator

class ChatMessage(BaseModel):
    role: str = Field(description="'user', 'assistant' o 'system'")
    content: str

    @field_validator("role")
    @classmethod
    def validar_rol(cls, v: str) -> str:
        roles_permitidos = {"user", "assistant", "system"}
        if v not in roles_permitidos:
            raise ValueError(f"role inválido: '{v}'. Debe ser uno de {roles_permitidos}")
        return v
```

### C. Configuración Robusta con `SecretStr` (`LLMConfig`)
Uno de los riesgos de seguridad más frecuentes es la **fuga de credenciales en logs de monitoreo**. Si imprimes un objeto de configuración con una API key normal, la clave se expone.

Pydantic provee `SecretStr`:
* Al hacer `print(config)` o serializar a JSON, la clave se oculta como `'**********'`.
* Para acceder al valor real al llamar al SDK, se utiliza explícitamente `.get_secret_value()`.

```python
from typing import Optional
from pydantic import BaseModel, Field, SecretStr

class LLMConfig(BaseModel):
    provider: Provider
    model: str
    openai_api_key: Optional[SecretStr] = None
    anthropic_api_key: Optional[SecretStr] = None
    google_api_key: Optional[SecretStr] = None
    temperature: float = Field(default=0.7, ge=0.0, le=2.0)  # Rango 0.0 a 2.0
    max_tokens: int = Field(default=1024, gt=0)              # Entero positivo
```

### D. Respuesta Estandarizada (`ModelResponse`)
Independientemente de si respondió OpenAI, Anthropic o Gemini, la respuesta siempre contiene los mismos atributos:

```python
class ModelResponse(BaseModel):
    provider: Provider
    model: str
    content: str
    error: Optional[str] = None
```

## 3. Ejemplo de Validación Preventiva

```python
from pydantic import ValidationError

try:
    # Error: temperature excede el máximo permitido (le=2.0)
    config = LLMConfig(provider=Provider.OPENAI, model="gpt-4o", temperature=4.5)
except ValidationError as e:
    print("✅ Interceptado ANTES de tocar la red:")
    print(e)
```
