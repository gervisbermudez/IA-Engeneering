# 4.1 Pinecone Serverless, Ingesta Batch y Namespaces

## 🎯 Objetivo de la Unidad
Aprender a desplegar y gestionar una infraestructura de base de datos vectorial administrada en la nube con Pinecone Serverless, optimizando la ingesta de millones de vectores mediante procesamiento por lotes y segmentación con namespaces.

---

## 1. ¿Por qué Pinecone en Producción?

Mientras que ChromaDB es excelente para entornos locales, las arquitecturas empresariales requieren:
* **Arquitectura Serverless**: Desacoplamiento de cómputo y almacenamiento; pago por uso sin gestionar instancias de servidores.
* **Escalabilidad Horizontal**: Consultas con latencias de milisegundos sobre millones o miles de millones de vectores.
* **Alta Disponibilidad y Persistencia Garantizada**.

---

## 2. Conceptos Clave de Infraestructura

* **Index (Índice)**: El contenedor principal. Define:
  1. Dimensión del vector (debe coincidir con el modelo de embeddings, ej. 1536 para OpenAI).
  2. Métrica de similitud (`cosine`, `dotproduct`, `euclidean`).
* **Namespaces (Espacios de Nombres)**: Particiones lógicas dentro de un mismo índice. Esencial para **multi-tenancy** (aislar los datos del Cliente A de los del Cliente B) o separar entornos (`dev`, `staging`, `prod`).
* **Metadatos**: Diccionario JSON almacenado junto con el vector. Permite filtros rígidos (*hard filters*) como `category == 'finanzas'` o `year >= 2024`.

---

## 3. Ingesta Eficiente: Batch Upsert

> [!CAUTION]
> Subir vectores de a uno por llamada HTTP es un error grave de rendimiento por overhead de red y límites de API. Siempre se deben enviar en **lotes (batches) de 100 a 200 vectores**.

```python
from pinecone import Pinecone

pc = Pinecone(api_key="PINECONE_API_KEY")
index = pc.Index("mi-indice-serverless")

# Ingesta en batches de 100 vectores
batch_size = 100
for i in range(0, len(vectores_preparados), batch_size):
    batch = vectores_preparados[i : i + batch_size]
    index.upsert(vectors=batch, namespace="documentos-legales")
```
