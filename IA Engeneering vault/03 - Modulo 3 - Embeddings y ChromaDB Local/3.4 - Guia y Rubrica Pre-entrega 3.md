# 3.4 Guía y Rúbrica: Pre-entrega 3 (RAG Local)

## 🎯 Qué Construir
Un flujo **End-to-End de RAG local** funcional que integre memoria vectorial persistente en ChromaDB con generación fundamentada (*grounded*), asegurando que el LLM no alucine respondiendo únicamente con el contexto recuperado.

---

## 📊 Rúbrica de Evaluación (Total: 100 pts | Aprobación: 70 pts)

| Criterio | Peso | Requisitos Clave |
| :--- | :---: | :--- |
| **Estrategia de Chunking e Ingesta** | **25%** | • Procesamiento de archivos `.txt` o `.md` de la carpeta `/data`.<br>• `RecursiveCharacterTextSplitter` con al menos 500 tokens y 50 de overlap. |
| **Arquitectura Asíncrona y Recuperación** | **35%** | • Función asíncrona `get_rag_response(query: str)`.<br>• Búsqueda de similitud y llamada asíncrona al LLM. |
| **Validación con Pydantic y Esquemas** | **20%** | • Modelo Pydantic que valide la salida conteniendo el texto de la respuesta y las fuentes/referencias utilizadas. |
| **Robustez y Evidencia de Pruebas** | **20%** | • Prueba positiva (pregunta con respuesta en los documentos).<br>• "Pregunta trampa" (pregunta fuera de contexto donde el modelo debe decir "No tengo información" sin alucinar). |

---

## 📂 Estructura del Repositorio
```text
sistema-rag-local/
├── data/               # Archivos .txt o .md de ejemplo
├── ingest.py           # Script de carga, chunking y persistencia en ChromaDB
├── rag.py              # Clase/función get_rag_response() con LCEL y prompt grounded
├── schemas.py          # Modelo Pydantic para respuesta y fuentes
├── main.py             # Script de prueba (pregunta válida vs pregunta trampa)
├── vectorstore/        # Directorio de datos persistidos de ChromaDB
├── requirements.txt
└── README.md
```
