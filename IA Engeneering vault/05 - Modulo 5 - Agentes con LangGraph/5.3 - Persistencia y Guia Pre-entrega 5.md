# 5.3 Checkpointers (SqliteSaver) y Guía Pre-entrega 5

## 🎯 Objetivo de la Unidad
Implementar persistencia de sesiones de razonamiento mediante Checkpointers (`SqliteSaver`), asegurando que las conversaciones y el historial de herramientas sobrevivan a desconexiones basándose en `thread_id`.

---

## 1. Checkpointers: La Caja Negra del Agente

Un **Checkpointer** toma una "fotografía" del estado del grafo después de cada nodo ejecutado:
* **Recuperación ante caídas**: Si la conexión se corta a mitad de un razonamiento de 5 pasos, el sistema no vuelve a empezar de cero ni repite llamadas costosas.
* **Multisesión**: Basta con asociar cada usuario a un `thread_id` único para mantener historiales de chat completamente independientes en la misma base SQLite.

```python
from langgraph.checkpoint.sqlite import SqliteSaver

with SqliteSaver.from_conn_string(":memory:") as checkpointer:
    app = workflow.compile(checkpointer=checkpointer)
    
    config = {"configurable": {"thread_id": "sesion_usuario_123"}}
    # Primera interacción
    app.invoke({"messages": [("user", "Hola, me llamo Carlos y vivo en Santiago.")]}, config)
    
    # Segunda interacción: el agente recuerda el nombre gracias al thread_id
    res = app.invoke({"messages": [("user", "¿Cómo está el clima en mi ciudad?")]}, config)
```

---

## 2. Control de Bucles: `recursion_limit`

> [!CAUTION]
> En agentes autónomos, un error en las respuestas de una herramienta o una condición ambigua puede causar un bucle infinito de llamadas consumiendo tokens y dinero.
> Configura siempre un techo explícito:
> ```python
> app.invoke(inputs, config={"recursion_limit": 10})
> ```
